# 依赖方案选型与技术说明：
# 1. pypdf (BSD-3-Clause 许可证)
#    - 选用版本: >=5.0.0,<=6.21.4 (推荐 6.21.4)
#    - 选型理由: 纯 Python 实现，无系统级 C 编译依赖，启动极快，内存占用低；
#      原生支持页面遍历、文本提取、加密与权限检测、格式校验；
#    - 替代方案评估:
#      * PyMuPDF (fitz): AGPL-3.0 许可证，存在商业与开源许可合规风险，且依赖 C 扩展；
#      * pdfplumber: 依赖 pdfminer.six 与 Pillow，依赖树庞大，在纯文本提取场景下偏重；
#      * pypdfium2: 依赖 Google PDFium 预编译动态链接库，跨平台部署复杂度高。
#    - 结论: pypdf 是在无 OCR 场景下提取结构化纯文本最安全、免环境依赖的轻量方案。
#
# 2. python-docx (MIT 许可证)
#    - 选用版本: >=1.1.0,<=1.1.2 (推荐 1.1.2)
#    - 选型理由: Python 生态处理 Office Open XML (.docx) 的工业级标准库；
#      支持按文档原始流顺序访问段落与表格元素，支持内置标题级（Heading 1-6）识别与提取；
#    - 替代方案评估:
#      * docx2txt: 功能单薄，丢失标题级别与表格结构，不利于分块索引；
#      * mammoth: 主要目标为转 HTML，引入额外复杂映射。
#    - 结论: python-docx 能够保证段落与表格按自然阅读顺序流式重构，完美兼容现有分块引擎。

pypdf>=5.0.0,<=6.21.4
python-docx>=1.1.0,<=1.1.2
