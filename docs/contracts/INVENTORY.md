# 旅程背包数量账本 v1.0

## 数据与身份

character.inventory为可选数组，元素仅{name,quantity}。旧角色缺字段时按空背包参与计算，旧快照仍保持原样；无角色的旧旅程不自动创建角色。

物品名称先去首尾空白，再做Unicode NFC归一，1–80字，不含控制字符或不完整Unicode。归一后的名称是该旅程的物品组标识，大小写仍区分；同名物品不可拆成不同实例。数量须为整数1–9999，最多40种；零数量的组不保留。初始化重复归一名称拒绝，网页编辑器可合并同名输入。

这不是装备、耐久或唯一物品实例系统。程序不自动同义词匹配（“干粮”和“口粮”不会合并），也不判断品质或物品真实性。

## 提议

仅有角色上下文的请求可在proposed_changes中附加inventory_changes数组。每项仅{name,delta}；单次最多40项，每个归一名称只出现一次，delta为非零整数-99..99，不接受bool/浮点。增加不存在的名称会建立新组；扣减不存在或不足的物品会拒绝整份提议。数量减至0移除该组，最终种类数/数量超限拒绝。

示例：{coins_delta:-3,inventory_changes:[{name:"干粮",delta:1}]}。

生成不改变背包。仍用原commit apply_changes:true明确采用整份状态提议，物品与铜币/体力/时间同事务写入；缺省false仅记录叙事。任一字段非法都不会部分结算。状态前后快照包含背包，重试/并发保护沿用角色账本与旅程revision，不能重复获得或消耗物品。

模型提议是待审阅数据；程序只校验范围与数量，不证明交易、掉落、物品价值或因果合理。Fake在容量允许时提供固定“测试纪念签+1”演示并明确标注，不声称理解自由行动。玩家应核对提议后选择是否采用。
