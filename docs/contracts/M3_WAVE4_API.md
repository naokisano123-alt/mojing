# M3 第四轮接口约定

## 从资料建立初始局势

- 选择现有资料、起点及开局时间，复用已有导入文本、确认设定和模型会话。真实分析由玩家在界面主动发起，说明会使用 API。导入本身只保存资料。
- 输入是当前世界的一组有限资料节选、允许引用的来源 ID、起点和时刻。文件较长时分批提取，再合并结果。源文本是供分析的资料，文内指令不具有系统权限。
- 输出以稳定的实例内人物和地点标识、事件线、人物动机及已知关系为主。来源有明文支持时附有效引用。资料空白允许 AI 补写可成立的局势，将补写记录为该旅程的推演。已有设定冲突要保留或提示，角色未获知的设定不进玩家开局摘要。
- 分析生成草案，确认后原子建立旅程状态并绑定来源。重试、重开和分支须能区分。初始化失败后可重试，未确认草案不写入正式事件、人物、知识与时间。

## NPC 推演

- 既有 `npcs.read_snapshot`、`npcs.validate_proposal` 和 `npcs.apply_proposal` 作为模块边界。AI 读取当前时刻、到期人物、已知事实、动机与相关事件，决定等待、改变计划、出行或交谈。程序记录行动和状态，沿用来源、时间、知情范围与世界实例检查。
- 玩家确认推进游戏时间后，使用现有可选世界脉动与模型预算。无到期任务不请求模型。关闭脉动、进入后台或失去连接时暂停，恢复时以当前确认时间为锚。模型调用使用同一受控队列，提交时核对活动租约、任务身份和实例版本。
- 组合提交时只推进一次实例版本。现有 NPC 应用默认会推进版本，集成时须明确由谁更新，保留单独调用时的现有语义。失败整体回滚，重复执行同一任务不会再添加行动或消息。
- 已发生的 NPC 行动改变后续可接触性。玩家从当面交流、公告等有效途径得知的内容才能进消息或叙事。NPC 改计划可以改变之后的选择，玩家仍以自由文本行动。

## 手机端联调

Ma 通过可注入 transport 开发，方法名由包内定义并记录。交付资料选择、起点、分析状态、草案摘要及确认结果五类数据。状态覆盖等待、分析中、可确认、失败可重试和已应用。摘要仅给玩家应知的内容。DeepSeekHarness 将组件接入世界资料与旅程入口，真实模型密钥沿用现有设置。
