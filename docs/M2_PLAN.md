# M2 执行方案

状态：M2-A开始开发。用户已反馈安卓已测流程正常，并授权继续推进和分工；详细设备与逐项验收未登记，见[M1记录](M1_ACCEPTANCE.md)。

## 本阶段

采用OpenAI兼容接口、自填base_url/model、Key仅在后端会话内存保存；连接测试可能有少量费用，由用户点击触发。不展示编造的费用估算，暂不承诺完整用量计费。建议叙事300–600字，程序限制最大12000 UTF-16单位。失败明确提示、保留输入，手动重试，不自动降级Fake。

先交付独立“模型叙事实验”：用户行动+当前世界有限资料→叙事草案+可核对来源。结果不提交角色状态、时间或存档。初版完整JSON响应，停止/超时取消生成任务；流式另行扩展。

Codex本轮交付：纯输入/输出校验、FakeModelClient、可注入ModelClient协议与18条回归。当前还没有可点击的M2入口或真实模型路由，等待四包集成。详见[冻结契约](contracts/M2_A_API.md)、[ROUND6](collaboration/ROUND6.md)。

## 阶段顺序

1. M2-A：内存会话、连接测试、Fake/Live草案预览、停止/重试和来源。
2. M2-B：验收模型调用后，再设计正式回合草案与单回合原子提交，明确取消/重试的提交边界。
3. M2-C：流式输出、用量反馈与长文本阅读优化。
4. M3：正式状态、知识权限、长期事件与分支引擎。
