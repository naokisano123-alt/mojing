# 墨境 M2 规划（仅规划，不实现）

> 状态：**提案**。本轮不写真实模型客户端、不收 Key、不做 M3。
> 前置：M1 验收记录见 [M1_ACCEPTANCE.md](M1_ACCEPTANCE.md)。M1 未完成前不进入 M2 开发。

## 1. 目标

在 M1 的世界资料库之上，接一个用户自选的模型服务，把"自由输入 → 叙事 → 状态变化"跑通成**可停止、可重试、有引用**的最小闭环。

## 2. 需要先定的产品决策（需用户回答）

| # | 决策 | 选项 |

| 1 | 支持哪些服务商 | 仅 OpenAI 兼容接口 / 再加 Anthropic / 只允许自建 |

## 3. 技术轮廓（提案）

### 3.1 连接与 Key

- 前端**不直接**持有 Key；后端做代理，Key 只在服务端内存/加密存储
- 新增 `POST /api/v1/models/test`（连通性）、`POST /api/v1/turns`（一次回合）
- 流式：SSE 或分块响应；前端必须能取消（`AbortController`），取消后服务端不再提交状态

### 3.2 输出契约（关键）

模型只产出**草案**，程序负责提交：

```text
玩家行动 → 组装上下文（世界设定引用 + 最近事件 + 角色状态）
        → 模型输出 { narrative, proposed_changes[], references[], elapsed_minutes }
        → 结构与规则校验（JSON Schema + 业务规则）
        → 原子提交事件与状态（失败则整回合回滚）
        → 返回 narrative + 状态卡
```

- `proposed_changes` 必须白名单化（体力/精神/铜币/时间/地点/关系），模型不得直接写数据库
- `references` 指向 `lore_entries` / `chunks`，用于"这句话依据哪段设定"的回溯
- 引用越权（NPC 知道未公开秘密）由程序判定，不让模型自证

### 3.3 可测试边界

- 提供 `FakeModelClient`：固定输入 → 固定草案，用于跑通管线与失败分支
- 超时、限流、格式错误、内容截断各有独立用例，不靠真实付费调用

### 3.4 不做什么

- 不做多人、云同步、后台 NPC 自治、OCR、语音、自动地图
- 不做 M3 的完整事件溯源与分支事务；M2 只保证单回合同步提交

## 4. 里程碑建议

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| M2-A | Key 管理与连通性测试（假实现） | 不落盘、可删除、错误可读 |
| M2-B | 单回合管线（FakeModel） | 草案校验、原子提交、失败回滚 |
| M2-C | 真实模型接入 + 流式 + 取消 | 中途停止不产生半提交 |
| M2-D | 引用回溯与费用提示 | 每条叙事可查依据段落 |
