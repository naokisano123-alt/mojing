# 开局容错：以可玩性为先，保留存档与世界边界

## 问题与取舍

真机开局被 `relationships[2].source_ids` 缺失拦截。模型把推演的人物关系标成 `canon`，却没提供直接资料出处。用户明确希望允许合理补写，避免为技术标注反复卡住开局。

本次只对 **AI 初始局势生成结果** 做本地整理：

- 地点、事件、人物、内嵌和顶层人物关系的来源标注统一整理；有效引用保留，单字符串来源转为列表。
- 缺失、空白、格式错误或无法核对的引用不再直接使生成失败；去掉无效引用，将相关内容标为 `adventure_supplement`，记录为本旅程推演，不冒充世界观原文。
- 对象不存在、自指或没有有效描述的可选人物关系略过；可用人物和开局仍然保留。关系描述长度和非标准可见性标注做保守整理。
- 已知属于其他世界的真实来源仍然拒绝；没有放宽正式领域提议、角色账本、事务或迁移校验。
- 不修改导入的原文，不额外调用模型，不自动重试付费请求。已有开局请求幂等机制继续生效。

已有的地点去重和编号整理，以及私密事件的玩家已知信息判定继续沿用。本文的来源整理不会把隐藏事件自动公开，也不会把任务直接结算。

推演内容可能继续携带当前世界的有效上下文锚点，这是原有领域账本所需的归属记录，**不等于直接引文证据**；`grounding_type` 和补写说明保留推演身份。丢弃的伪造来源不会进入存档。

## 界面

无法整理的初始局势结构错误使用简短提示，保留开局文字；错误代码放入折叠项。跨世界错误单独说明。连接、鉴权等错误仍显示原有可操作提示。

没有把所有校验错误静默忽略，也没有宣称可以验证任意故事的语义正确性。

## 验证

- 新增后端用例覆盖缺失/空列表/空字符串/伪造引用/错误类型、有效单字符串引用、真实跨世界拒绝。
- 生产开局路由通过：解释开局 → 宽松分析 → 创建旅程 → 同请求重试不重复调用 → 自动存档 → 读档 → ZIP 导出导入；不含已丢弃的伪造来源。
- 无法恢复的分析错误回滚，不留下半成品旅程或挂起的请求。
- 前端用例验证简短错误提示、原文保留、诊断默认折叠、没有自动重试调用。
- 后端全量：503 项及 5 项子测试通过；前端 Vitest：84 项通过；Node：77 项通过；生产构建通过。

本轮没有用户真实服务商 Key，没有声称完成真实付费模型或安卓真机验收。APK 构建由仓库 Android workflow 完成后再交付。
