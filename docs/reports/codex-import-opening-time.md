## 导入后退出看似回退

确认了三个实际缺口：主页把导入成功直接接到“进入世界”，没有同步登记导入副本；导入副本与原世界同名，退出后难以区分；主页只读取前 50 个世界，后续副本可能不在列表。它们都可能使玩家重新进入原世界，不能据此宣称手机 SQLite 发生了事务回滚。

本次改为：

- “新的世界与冒险”统一提供从头创建、导入世界或存档两个入口；导入表单直接嵌入，不叠加第二个弹窗。首页不再单列导入按钮，示例世界折叠展示。
- 创建与导入共用世界登记流程，按服务端返回的独立 ID 插入列表；列表翻页取全，使用请求代次防止旧请求覆盖新状态。
- 最近进入的世界按设备偏好排在前面，旅程选择仍按世界 ID 隔离。
- 正式 M3 可移植导入和兼容导入共用同名命名规则：同名时追加“（导入）”“（导入2）”，保持 40 字限制。不覆盖原世界；来源摘要与 ID 映射继续保留。

回归测试走正式导出/导入/冒险路由与模型 HTTP 模拟：原世界 1 回合 → 同设备导入 ZIP → 导入副本续玩至 2 回合 → 返回列表并重入 → 重启服务、重新绑定模拟 API → 续玩至 3 回合。导入副本钱币与历史持续增长，原世界仍为 1 回合。React 装配测试还验证超过 50 个世界、导入后确认新回合、退出重入同一副本。

## “资料开局”与手动开局

二者进入同一套冒险系统。资料开局多一步预先分析资料、准备起点/人物/初始局势，并由玩家确认；直接开始则省去预分析，仍可以在冒险中参考世界资料。界面改用“让 AI 根据资料生成开局”“返回手动开局”，并用短说明解释差别，详细费用说明折叠。

初始分析的客户端原来用 `except Exception` 把 `_content` 抛出的截断、空正文、未完成等错误一律包装为 JSON 解析失败，因此截图无法确定那一次服务商实际返回了什么。本次保留原错误类别，仅对真实的 JSON 语法错误报告解析失败，并给出可操作提示。不会自动重试付费请求。

针对官方 `api.deepseek.com`：开局分析和世界脉动发送 `response_format=json_object`；现代 `deepseek-flash` / `deepseek-v4-pro` 的上述结构化任务显式禁用默认思考。普通叙事的模型策略未改，对其他兼容端点不发送这些选项。开局分析提示要求简短的必要地点、人物和事件，输出上限仍为 8,192 Token。

已核对官方文档（2026-11-11）：

- [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)：JSON 输出参数、空白回复情况和输出额度要求。
- [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)：当前默认开启思考、关闭参数及独立 reasoning_content。

## 阅读时间与行动

- 正文顶部和回合时间摘要显示“第几天 · 上午/下午/夜晚”，不显示默认的 1000 年日期和小时分钟；角色卡移除累计分钟展示。
- 删除“指定快进时长/快进小时数”控件。内部分钟、日程、人物到期、脉动和存档仍按原精度计算。
- 自由行动支持“等待两个小时”“休息半天”“做工三天”“睡一夜”等明确时长，继续使用原来的时间上限、事件中断与确认机制；不会把“询问三天前的事”“不等两小时”等识别为快进。更自由的行动仍由叙事模型结合当前时间提出变化。
