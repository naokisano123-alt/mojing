# M3 技术架构审查

审查日期 2026-11-09。代码基线为 [主分支 9388278](https://github.com/naokisano123-alt/mojing/commit/9388278f8a334f457e92ed820cc5b2456c76dfd8)。需求来自[用户总纲](../M3_DESIGN_DRAFT.md)，本轮冻结的交付边界见[协作任务](../collaboration/M3_WAVE1.md)及[集成契约](../contracts/M3_WAVE1_API.md)。

## 判断

总纲值得按阶段实施。最有价值的三项是独立世界实例、程序结算和玩家视角投影。建议把「第一阶段 18 项验收」拆成多次发布关口。先证明事件能在正确的分支提交、能回档，再打开后台模型。否则一次异步覆盖可能同时污染角色账本、事件历史和存档，难以定位。

1. **复用已有时钟。** PR #22 已有开局快照、按游戏分钟推进、停在作者设定的关键事件、分支和跨设备迁移。M3.0 把已确认的游戏分钟接到实例层。世界脉动只消费这段已确认时间。现实时间可用来判断任务租约和重试时机。
2. **把重大历史变化做成可追溯的候选提议。** 程序可以验证版本、引用、时间顺序、数值和已登记的硬约束。历史是否合理还要由资料约束、阶段性因果和测试场景共同检验。第一版先用可复现的贸易事件链验证，广泛经济和 NPC 群体模拟排在后面。
3. **把玩家视角定义为单独的输出。** 即使事件已经发生，玩家也只通过观察、公告、对话等渠道获得信息。玩家 API、用于叙事的模型上下文、提示数量和错误信息使用同一套投影语义。作者日程页仍是单独入口。当前服务器是本地单用户设计，角色知识隔离与账号鉴权是两层设计。
4. **分开世界脉动和前台叙事的凭据生命周期。** 当前安卓版已有本机加密的叙事模型记忆功能。新增脉动连接默认内存态，独立或复用当前叙事会话均可。失效后暂停付费任务，重连后再继续。模型用量优先记录服务商返回的 usage，估算数据独立标识。

## 分段验收

- **M3.0** 先验证旧库幂等升级、旅程实例隔离、检查点精确恢复、旧包兼容和新包迁移。需要覆盖同一游戏分钟先存档、再由后台改变世界的情况。
- **M3.1** 以 Fake 实现 3～6 条初始事件线、一次有效推进和一次拒绝非法提议。再用 OpenAI 兼容 Mock 验证模型响应解析。初始种子只从本次授权的世界资料生成。
- **M3.2** 接持久队列、会话和预算。开关默认关闭，后台任务只处理已确认时钟。覆盖工作进程重启、会话失效、并发领取、重复提交、后台与前台竞态。
- **M3.3 首条闭环** 同一事件可以被甲知悉、被乙误信、对玩家仍隐藏。经过具体传播渠道后，玩家才看见对应版本。知识保护须先通过，才把异步事件接入前台叙事。完整 NPC 分级、经济和开放行动按总纲后续阶段推进。

## 迁移与回退

迁移只做幂等增量，保留原 SQLite 数据和角色账本。开发时先在复制库上验证重复启动、失败回滚和新旧包导入。上线回退先关闭脉动并停止 Worker，保留事件和记录；旧版本必须经升级库副本测试才能用于降级，遇到不支持的存档格式应报清楚版本错误。应用版本降级不能冒充数据回滚；真正的数据回滚使用升级前备份。

本报告核对了主分支代码和现有契约，本次交付为架构审查和任务书。运行结果由后续实现 PR 和集成报告逐项登记。
