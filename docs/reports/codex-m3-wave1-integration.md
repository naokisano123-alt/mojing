# M3 首轮集成复审

基于 DeepSeekHarness 的 `feat/m3-combined`（`0a9f78a`）。三份 Gemini 导入提交和原集成提交都保留在 Git 历史中。

| 交接项 | 处理 |
| --- | --- |
| `world_instances.revision` | 数据库只用 `revision`，对外保留 `world_revision`。迁移原组合底座的旧列，补建实例时从旅程读已确认的分钟和版本。回合推进使用实际确认的角色时间差。 |
| `world_events` | 事件账本拥有表结构，知识层从账本读取。共存测试使用真实表，关闭 Windows 测试里的 SQLite 连接。 |
| 脉动开关 | 模拟旅程的「世界消息」里有开关，默认关闭。启用时由真实队列生成三条模拟事件线，回合确认后推进到期事件。玩家通过公告获得传闻，关闭期间的分钟不会回补。 |
| 快照体积 | 保留全量快照，确保同一游戏分钟的多个版本能准确分叉。存档列表不再读取或返回快照。可迁移存档 v4 按实例导出领域状态，导入时重映射引用，排除任务、开关、会话和凭据。 |

## 手动验收

1. 导入一份世界资料，或确认一条人工设定。
2. 创建模拟旅程，展开「世界消息」并开启脉动演示，刷新消息可看到第一条公告。演示使用固定规则，不产生外部模型调用。
3. 确认使游戏时间推进的回合，到期事件会进入队列。新消息生成后可点「刷新消息」。关闭期间可以继续游戏，重新开启后从当前时间继续。
4. 导出迁移 ZIP，再导入到另一份数据库。角色、历史回合、事件、已获知消息和检查点可恢复。新实例的脉动开关默认关闭。

## 验收边界

- 在 Linux 运行了全量后端、前端和生产构建。真实模型推演、叙事提示词接入、Windows 原生复测和安卓真机验收分别留待验证。
- 检查点及可迁移存档是玩家主动管理的两类接口。世界消息及存档列表只返回玩家界面字段。可迁移存档 v4 会包含用于完整续玩的内部事件状态。
- v1–v3 的存档仍可导入。如果 v4 事件引用的资料在导出前已被删除，导入校验会拒绝该引用。历史来源归档和大型存档的增量快照需要后续设计。
