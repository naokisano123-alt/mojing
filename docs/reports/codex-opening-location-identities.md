# 开局地点身份冲突修复

2026-11-12，基线 main a81b364。修复安卓开局出现“locations[2]存在重复的地点标识或名称：王城正门（loc_capital_gate）”而无法继续的问题。

模型中的 location_id 是本次生成使用的标签。原合并器按地点名称合并，却没有修复不同名称共用同一编号；校验器随即把整份初始化拒绝。新逻辑在完成来源、跨实例与长度检查后，为不同名称但重号的地点确定性地分配独立编号，保留名称、来源及描述。人物与事件原本使用地点名称定位，不需要随临时编号改写玩家开局。

同名重复记录在合并阶段及直接校验路径均可合并，来源取并集，描述和区域的差异保留在 identity_resolution_log 供核对。当前一版只保留推演说明而后一版有明确资料依据时，选资料说明。不同公开程度按更保守的范围处理，避免重复记录将私密地点变为公开。现有原文资料冲突记录保持独立，不通过编号修复选择世界设定的真假。模型漏掉起点时自动补充地点，也保证其编号不会与已有地点相撞。

这里不进行模糊地名合并：王城正门与王城大门等不同名称保留为不同记录，不仅凭同一编号断言它们是同一地点。同名记录的区域差异仍需要世界设定的地理消歧；本轮保留审计与原文，不声称自动解决所有同名异地问题。

新增6项测试覆盖相同编号对应不同名称、同名记录的证据与可见性、自动补充起点的编号冲突、安全检查、实际开局与请求幂等→自动存档→读取→ZIP迁移，以及跨批合并差异。修复使用本地归一化，不增加付费模型重试。

本地全量后端494项测试及5项子测试、生产构建已通过；模型调用均为Mock，未使用真实服务商Key，未做安卓真机回测。最终CI和APK构建另行复核。
