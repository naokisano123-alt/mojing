# 手机世界脉动与重复日志修复

用户在 Android 包中点击独立模型连接或复用叙事会话，均收到 Method Not Allowed。刷新旅程后还出现多份相同的当前角色状态和世界日志。

## 原因与修复

前端默认传输层将连接请求发送到 `/world-pulse/session`，正式后端仅注册 `/world-pulse/connect`。在包含静态网页的本机应用内，错误地址落入静态文件处理，POST 返回 405。统一到正式连接地址后，两种连接方式均可绑定会话。连接、启用和付费模型推演仍沿用现有流程。

当前角色、世界日志和脉动控制在同一父节点内使用相同的 React key。组件更新时会错误复用节点，页面中留下重复状态卡和日志。已改为按功能区分的稳定 key，并处理世界消息内的同类冲突。

世界日志收起时不再渲染内容。说明文字缩短，押金更正与余额结算的说明移到实际编辑押金时。历史回合中的完整角色卡改为点击「查看本回合状态」后查看，当前状态与历史详情可分别读取。

## 验证

- 新增回归测试在修复前复现了三份「当前角色状态」。修复后连续刷新四次，当前角色和世界日志始终各一份，也没有相同 key 的警告。
- 新增本机接口测试直接读取前端默认传输层的实际请求路径和方法，针对带网页挂载、登录和 Origin 校验的应用验证独立连接与复用叙事会话，避免前后端只测各自替身而漏掉接口偏差。
- 额外运行 React 页面与正式 FastAPI 本机应用的跨进程联调。点击独立连接、改为复用、确认启用、生成并确认行动，世界脉动完成初始化和一次事件更新，玩家收到对应世界消息。随后连续刷新四次，当前角色和日志各一份。模型服务使用 HTTP 替身，无真实费用。
- 图形浏览器在此环境内启动受限，上述页面联调使用 jsdom 和 ASGI 请求桥。Android 真机交互及真实服务商仍需用户复测。
