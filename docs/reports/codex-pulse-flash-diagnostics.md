# 世界脉动默认模型与失败排查

基线：`77cef750ad8a5ce58b8a178685d9c02f803257ba`（世界工作区界面合并后）。

## 证据与判断

用户手机截图显示独立会话已绑定 `deepseek-flash`，有一次可能计费请求、实际用量 3,793 Token，随后显示“最近一次推演失败”。这支持请求已到达模型并返回用量，不能据此认定 API Key 或模型名称错误。截图不含具体任务错误码，无法读取手机本地数据库或重建那次真实回复，因此不能断言唯一根因。

检查发现两处实际缺口：

1. 初始局势提示词没有说明 `scope` 必填以及合法枚举，而领域校验严格要求它。已有 `PULSE_EVENT_OUTPUT_SCHEMA` 留在提示词构建返回值中，正式脉动客户端只发送 system/user 两段，没有发送 Schema。模型按原文字说明输出、不填 `scope`，会得到 `VALIDATION_ERROR`，整批事件不写入。
2. 任务已保存具体错误码，但手机控制 DTO 仅返回 `PULSE_JOB_FAILED`，用户无法区分截断、非法 JSON 和领域校验失败。

另一个可能原因是输出截断：原正式 Worker 输出上限为 1,400 Token，而初始化要求 3～6 条事件。3,793 是输入与输出总数，不能单凭总数判断是否截断。客户端原本已正确识别 `finish_reason=length`，本次保留该拒绝行为。

## 修改

- 世界脉动独立连接默认填 `deepseek-flash`；手动模型输入、复用叙事会话仍尊重用户选择。
- 给初始局势和后续事件提示词补充紧凑字段契约，明确必填字段、枚举、数组和后果格式。没有发送整份冗长 Schema，也没有加入固定剧情模板或放宽校验。
- 初始化优先生成允许范围的最少三条事件，限制描述与摘要长度；正式 Worker 输出上限从 1,400 调整为 2,000 Token，实际可用输出仍按每轮总预算裁剪，每轮/每日预算不变。
- 控制 DTO 加性返回可选 `reason_summary`，供现有界面显示失败类别及已知错误码。不返回模型原文、动态校验值、隐藏事件或凭据；未知错误使用固定通用说明。恢复成功后清除旧错误说明。
- 同步因果链 fixture 中四个提示词长度统计，事件及因果数据未变。

## 验证范围

- 正式应用 HTTP 路由 → 模型 HTTP 客户端（MockTransport）→ Worker → 事件领域校验 → SQLite：模拟缺少 `scope`、截断、非法 JSON、未知字段，均确认失败不写事件、已返回用量仍结算、不自动重复付费，用户关闭再开启后可创建三条事件。
- 手机组件：默认模型、显示失败类别、刷新恢复后移除旧错误、隐藏任务原文不进入界面。
- 本地前端 Node 75 项、Vitest 74 项、生产构建通过；后端全量 462 项及 5 个子测试通过。
- 本次无用户 API Key，未发起 DeepSeek 真实付费请求，也未声称完成安卓真机复验。下次失败时可直接查看“设置 → 世界脉动”的具体错误说明，进一步确定设备上的真实原因。
