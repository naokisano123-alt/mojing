# Gemini Ma · 玩家知情边界与手机端控制

只改 `server/app/m3/knowledge/`、`server/tests/m3/knowledge/`、`src/features/world-knowledge/`、新目录 `src/features/world-pulse/`、对应的 `tests/ui/world-knowledge/` 与 `tests/ui/world-pulse/`，以及 `docs/reports/gemini-ma-m3-wave2.md`。通过注入 transport 与 fixture 独立运行。

1. 给真实脉动输出提供传播纯校验和事务应用适配器。限制接收人、事件、获知分钟、渠道和可信度。转述人必须已获知对应内容，玩家只有通过亲历、公告或合法交流才获得消息。同一事件下保留不同 NPC 的认知版本。
2. 复用玩家投影构建独立、限长、可序列化的叙事数据块。消息 UI 与叙事输入都只能取得玩家已获知的记录，保持传闻和事实类型。拒绝跨分支引用，不暴露权威标题、真实事件 ID、隐藏总数、未来时刻和 NPC 私密事实。用提示词注入样本及分支对照证明投影只传送可见数据。
3. 开发手机端脉动控制组件，适配 [本轮接口约定](../contracts/M3_WAVE2_API.md)。独立配置优先展示，也支持复用叙事会话。连接和启用是独立操作，启用时明确提示额外消耗。提供关闭、等待重连、离线和预算不足等状态，展示实际/估算用量。Key 只在输入与请求期间存在，提交或卸载后清理。
4. 组件用注入的 transport 处理页面可见状态、切旅程与断网，并为集成方提供宿主调用说明。续期须有可见旅程，退出或进入后台尝试结束活动。清除旧请求与计时器，拒绝旧旅程响应污染当前页面。维持中文阅读、触屏和浅深主题可用性。
5. 端到端 fixture 覆盖「商队首领先得知改道 → 店主转述 → 玩家才看见」。再用手机宽度 UI 测试覆盖独立连接、复用、显式启停、失效重连和切旅程。提交测试证据和接线说明。

不要直接改冒险路由、`NarrationRequest`、模型网关或 `AdventureJournal.tsx`。报告列出最小挂载点和默认行为，DeepSeekHarness 负责接入。
