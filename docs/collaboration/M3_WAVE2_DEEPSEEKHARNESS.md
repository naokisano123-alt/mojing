# DeepSeekHarness · 独立导包、公共接线与验收

按 [本轮任务索引](M3_WAVE2.md) 导入三包。保留原提交与作者归属。共享代码使用新的集成分支和 PR，报告写入 `docs/reports/deepseekharness-m3-wave2.md`。

1. 审查每包的文件清单、基线、改动差异和独立测试。为三包分别开 PR，冲突记录受影响文件及两侧改动，禁止覆写已合入内容。任务书约定调整需先同步。
2. 接线应用生命周期、模型会话、旅程控制 API 和手机入口。复用现有同源、本机访问与服务商地址限制。用同一个实例版本和任务租约提交事件与知识变更。将玩家安全投影接到叙事请求，保留既有时间事件与角色日志行为。
3. 验收完整路径。默认关闭，只有显式开启且凭据有效、玩家在线、预算足够时才可发请求。Mock HTTP 跑通 Seed 与 Advance、公告或转述、叙事取用、离线恢复、关闭时在途模型、预算不足、分支、跨库迁移与已有无费用演示。涵盖同分钟不同版本和 API 错误不泄密。
4. 运行全量后端与前端测试、生产构建和 Android APK CI，附提交及工作流链接。真机和真实服务商只记录实际测试证据。没有真实测试则标记待验收；公开测试版本保持默认关闭。基线的 v4 已删除引用限制、全量快照体积单列，避免把迁移方案夹带进本轮。

合并公共接线之前，至少需要三个独立包通过各自验收、组合分支全量 CI 通过，并记录任何偏离接口约定的实现。
