# Gemini Ma · 人物知识、传播与玩家视角

先读[本轮入口](M3_WAVE1.md)和[契约](../contracts/M3_WAVE1_API.md)。完成 M3.3 的首条端到端闭环，为后续 NPC 自主行为提供可读的知情投影。

## 本轮交付

1. **按持有人隔离认知。** 实现事实、怀疑、传闻、误信四种记录。相同权威事件可以被不同 NPC 作不同理解。保存信息来源、渠道、游戏时间与可信度，支持分页和版本更正。持有人必须在同一个实例中，玩家身份由服务端绑定。
2. **可验证传播。** 实现亲历、公告、对话、传闻四类入口和至少一条多跳 fixture。例子可用商队消息先到酒馆掌柜，再由玩家交谈获得。禁止无来源授予、未获知的 NPC 转述、时序倒置及跨分支传播。消息在得知前对玩家完全隐藏。
3. **共用玩家投影。** 提供给前端和叙事上下文使用的安全读取。标题、数量、空态、分页游标、来源引用和错误信息均不能推断隐藏事件。用含提示词注入的传闻测试它始终作为不可信资料。已有 M2 秘密知情人保留，报告中给出后续对接边界。
4. **手机消息界面与快照。** 交付独立 React 消息面板，注入 transport，支持已知消息、来源、可信度及加载、空态、失败。实现知识快照与恢复；回到得知消息之前，分支仍看不到消息。完整 NPC 自主行为留给 M3.4。

## 文件和验收

拥有 `server/app/m3/knowledge/`、`server/tests/m3/knowledge/`、`src/features/world-knowledge/`、`tests/ui/world-knowledge/`。报告写 `docs/reports/gemini-ma-m3-wave1.md`。根路由和公共模型上下文接线由 DeepSeekHarness 完成。使用已提交事件/持有人 Fake fixture 和前端注入 transport，独立运行。

验收要覆盖两位 NPC 对同事件持不同说法、玩家获知前后对比、错误渠道及未来传播拒绝、隐藏信息零泄漏、旧检查点恢复、跨实例访问拒绝、移动窄屏与空态。
