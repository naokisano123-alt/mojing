# 墨境｜项目全貌、M0 交接基线与 M1 开发方案

更新时间：2026-11-08。读者：首次参与项目的 AI 或开发者。

## 1. 先读这一段

墨境是手机优先的 AI 文字冒险世界模拟器。用户导入自己的世界观资料，未来连接自选 AI 服务商，以自由文字行动扮演一个角色，在有规则、有记忆、有长期后果的世界里生活和冒险。玩家不必成为英雄，不强制主线，可以谋生、探索、建立关系，也允许失败和损失。

当前已经完成 M0：React + TypeScript + Vite + Tailwind CSS 的可交互手机网页原型。它用少量关键词和预置文本模拟回合，没有真实 AI、文档解析、后端或数据库。不要把 UI 上的演示存档、秘密和规则说明理解为已经完成正式状态机或 NPC 知识系统。

用户已试玩最新图鉴滑动修复版，并确认可以使用。下一阶段本文件建议进入 M1；本轮仅制定方案，尚未开始 M1 实现。

## 2. 产品目标与关键原则

- 自由输入：玩家用自己的语言决定说什么、做什么；建议行动只是辅助入口。
- 设定一致：用户资料是世界的依据。导入文本作为资料，不得当作系统指令执行。
- 因果持续：时间、地点、财物、关系与事件应延续，不能因下一回合换一段文字就重置。
- 知识有边界：玩家知道、角色知道、NPC 知道、创作者知道是不同范围。NPC 不能凭空知道未公开秘密。
- 可恢复：重要节点可以保存，恢复过去时建立新分支，保留原旅程。
- 手机阅读优先：正文是视觉中心，中文排版、软键盘、手势、草稿保护比装饰更重要。

正式系统的分工：AI 提供叙事和状态变更建议；程序校验并提交最终事实。不能让模型仅靠长 Prompt 记账，也不能先宣布行动成功、后发现状态提交失败。

## 3. 目标用户流程

我的世界 → 创建世界 → 导入 PDF/DOCX/TXT/MD → 查看原文和解析结果 → 整理并确认人物/地点/势力/规则等资料 → 配置自己的模型 → 创建角色 → 选择开局 → 自由冒险 → 查看角色/图鉴/时间线 → 保存或分支。

没有模型时仍可体验明确标注的演示模式。真实密钥与费用在 M2 阶段设计，不应在 M1 要求用户填写 API Key。

## 4. 已确认的界面与交互约定

### 4.1 页面层级

世界外：封面、我的世界、创建世界、主页设置。
世界内：故事、角色、图鉴、存档。

只有“我的世界”显示墨境品牌栏和设置入口。进入世界后隐藏品牌栏，不增加世界内设置按钮或点击时间地点打开设置的暗门。

设置拆成阅读、叙事、模型三个入口。阅读负责主题、字号、行距、状态卡展示；叙事负责文风及后续叙事偏好；模型暂为预留说明。主角光环不放在主页设置内。

### 4.2 故事页

时间和地点固定顶部，正文滚动时保持可见。右上角为贴近背景色、低对比的四分之一圆，只保留星芒图标，点击展开光环三档。不得用醒目文案、闪烁或主动提示鼓励玩家开启光环。

去掉 CHAPTER 01 等英文编号和大块留白，保留紧凑开篇标题。现有“雾中的第一盏灯”是预置标题。没有正式自动分章功能。未来只在实质阶段变化时分章，名称不剧透、不强迫主线，且不按每回合生成章节。

小说正文、玩家行动、状态变化独立呈现。小说模式可折叠状态变化；混合模式直接显示变化卡。

### 4.3 行动建议与输入

默认只显示建议和“…”；输入框收起。建议允许长文字、换行和增加高度。

- 短按建议：展开输入框，加入文字，不自动发送。
- 已有草稿时再点建议：换行追加，不覆盖手写内容。
- “…”：打开自由编辑；有草稿时保留，不能借此偷偷清空。
- 收起输入：保留草稿。
- 成功发送：清空并收起，显示后续建议。
- 停止模拟：保留行动文字和展开状态。
- 当前上限为 1000 字；超限追加失败时保留旧内容并提示。
- 草稿在当前应用会话中跨页面保留，尚未跨刷新持久化。

### 4.4 导航与退出

底部仅四个图标，依次为故事、角色、图鉴、存档。图鉴使用卷轴。保持足够触摸范围和无障碍名称。

左滑前往下一页，右滑返回上一页。在故事页额外右滑一次，提示“再右滑一次退出该世界”；2 秒内再次右滑返回我的世界，保留进度。主页同样右滑两次，返回简洁封面，不尝试关闭浏览器。

当前识别条件：水平位移至少 58px、至少为垂直位移的 1.7 倍、900ms 内完成。两次退出确认超时、反向、点击、纵向滚动或换页会取消。不要接管系统边缘返回。

### 4.5 已修复的滑动问题

旧实现将所有 button 和 .tabs 排除，导致图鉴卡片和分类条不能作为滑动起点。现已改成在捕获阶段识别：卡片、分类按钮、图标可横滑，轻点维持原操作；横向拖动后吞掉浏览器合成点击，避免切页同时打开详情。未发现卡片通过 pointer-events 委托滑动。输入框、弹层和 data-no-swipe 区域保留独立操作。

宿主的关闭/分享工具栏及“编辑网站”浮层不属于应用 DOM，不能通过墨境 CSS 移除。

## 5. 主角光环：命运干预

关闭：依设定自然推进，允许失败与损失。
温和：增加有来源、合乎规则的转机，仍需玩家争取。
强力：增加更明显的机会或援助，仍不保证成功。

三档均只影响未来回合，不撤销已成立事实，不凭空制造超规则道具，不代替玩家选择。切换记录到时间线；重试过去应读档并形成分支。

M0 只通过额外机会文案演示差别，不是正式概率或难度系统。

## 6. 当前实现边界

| 模块 | 已实现 | 尚未实现 |
| --- | --- | --- |
| 世界管理 | 预置卡片、新建名称/简介、独立演示进度 | 正式世界 CRUD、账户、云同步 |
| 文档入口 | 格式限制、记录/移除文件名 | 读取、上传、解析、检索 |
| 回合 | 预置文本、关键词匹配、加载/停止、状态反馈 | 任意自然语言理解、真实 AI、流式推理 |
| 状态 | 演示时间、地点、铜币、体力、精神 | 事务规则引擎、完整物品与 NPC 知识状态 |
| 图鉴 | 分类、搜索、详情、未发现占位 | 文档生成、真正发现权限与来源证据 |
| 存档 | 客户端快照、分支、切换、事件列表 | 正式事件溯源、数据库、跨设备恢复 |
| 设置 | 阅读偏好、两档模拟文风、模型占位 | 模型连接与密钥管理 |

所有预置和新建世界目前共享“雾港”演示开局、人物和图鉴；名称简介及模拟进度独立。演示设定不是用户的正式世界观。

“工作”+4 铜币、−8 体力、40 分钟；“买茶”−3 铜币并恢复少量体力；“休息”恢复体力精神；“探索”切换旧街/码头。其他行动明确提示未判定。多条建议组合仍只作为一条输入，关键词模拟不能保证依次执行所有动作。

## 7. 代码与运行

技术：React 19、TypeScript 5.7、Vite 6、Tailwind CSS 4、lucide-react。没有引入后端或重量级路由器。页面采用 hash 路由；当前浏览器 localStorage 键为 mojing-m0-v1。

src/interaction.ts           滑动判定、退出规则、建议追加

src/components/WorldBar.tsx  固定信息栏与独立光环弹层

src/pages/Story.tsx          叙事、建议、按需输入

启动：Node.js 22.18+，npm ci，然后 npm run dev。手机与电脑同一局域网时，用终端的 Network 地址访问。

检查：npm test；npm run build（包括 TypeScript 严格检查）。目前 17 项测试通过。手势回归直接执行实际 hook 处理器，覆盖卡片/按钮、分类条、图标、普通内容、轻点和输入框。

用户已真机试玩并确认图鉴修复可用。这不是所有安卓机型、键盘、横竖屏和长时间使用均已验收；仍需持续回归。远程浏览器原生拖动约 5 秒，会被正常慢拖过滤，不能据此声称已完成所有真实触摸测试。

## 8. 正式架构方向（规划，非现有实现）

前端继续 React + TypeScript + Vite；后端建议 Python + FastAPI；本地/自用阶段 SQLite + FTS5；验证层 Pydantic；表访问 SQLAlchemy 或 SQLModel 二选一。生产多用户阶段再评估 PostgreSQL。

状态分层：固定世界设定 canon_lore；玩家 player_state；NPC 状态与已知事实 npc_state/npc_knowledge；动态世界 world_state；事件与摘要 event_log/summary。

正式回合管线：行动携带 request_id → 加载状态、相关设定、NPC 已知事实、近期事件 → 模型输出 narrative/proposed_changes/events/elapsed_minutes/references → 结构与规则校验 → 原子提交状态和事件 → 显示叙事与状态卡。失败不能产生半提交或丢失玩家输入。

NPC 知识建议保留 fact_id、holder_id、known/suspected/mistaken、source_event_id、learned_at。世界 ID、会话 ID、分支 ID 分开；快照及事件版本化。

不让全部 NPC 全天后台推理。按玩家行动、旅行、休息及时间推进触发必要事件即可。

密钥不硬编码、不进入前端仓库或 localStorage；未来用后端代理和会话内存/加密存储。上传资料不可信；资料不能覆盖系统规则。正式上线再完成身份隔离、HTTPS、限制和日志脱敏。

## 9. 下一阶段方案：M1 文档导入与世界资料管理

### 目标

用户能真正导入自己的世界资料，检查结果、修改分类，并找到某个人物或地点对应的原文。此阶段维持演示冒险，不接真实 AI。

### 分步交付与验收

| 步骤 | 建议实现 | 验收 |
| --- | --- | --- |
| M1-A 数据与接口 | 后端最小服务；World/WorldDocument/LoreChunk/LoreEntry；独立于 M0 演示存储 | 新建、读取、编辑世界正常，重启服务后仍存在；旧演示进度不被覆盖 |
| M1-B 文本导入 | TXT/MD 优先；编码错误明确提示；保留原文与章节位置 | 导入可读中文文档，原文顺序正确；错误格式有反馈 |
| M1-C PDF/DOCX | 文本型 PDF、DOCX 正文及标题提取；扫描 PDF 明确不支持 OCR | 四种格式均可预览；空文件、损坏文件、扫描件有具体提示 |
| M1-D 人工整理 | 人物/地点/势力/规则等条目 CRUD；条目可关联原文块；待确认状态 | 人工建立和纠正条目，不丢失原始资料；暂不承诺 AI 自动提取 |
| M1-E 检索闭环 | SQLite FTS5 + 中文适配验证；原文预览定位 | 输入中文人物/地点名能找到原文及来源，条目详情可返回来源 |

优先用一个小型中文世界资料测试。第一轮可先完成 A+B 的最小闭环，再扩展格式，避免一开始堆满整个数据库模型。

### 重要实现取舍

1. 后端依赖和代码放独立 server/ 目录，前端通过 api/ 适配层访问，避免把解析逻辑塞进现有页面。
2. M0 的 localStorage 世界与正式 World 使用不同存储域或明确的迁移流程，禁止静默把演示资料当正式世界。
3. 初始分类由用户手工维护或明确标记的确定性规则辅助；无真实模型时不要把规则匹配包装成“AI 理解”。自动语义抽取可放 M2 或之后。
4. 中文全文检索不能直接假设默认 tokenizer 能按词匹配。先验证 FTS5 trigram 的运行环境及短词行为，必要时以安全参数化的子串检索作小规模降级方案，记录限制。
5. 重复文档检测、解析失败回滚、内容哈希、来源位置、删除引用处理要有明确行为；不要让条目留下失效的隐形来源。
6. 文件大小/数量限额、允许格式、失败重试及取消方式在 M1 开始时设为可配置的小范围默认值，用实际样本调整。
7. 继续遵守当前已确认的手机导航与输入交互，不在实现后端时重新设计整套 UI。

### M1 最低检查清单

四种格式的中文解析；标题/段落顺序；编码错误和空文件；损坏/扫描 PDF 提示；同名人物检索；条目纠错后保留原文来源；服务重启持久化；演示/正式世界隔离；手机上传/预览/返回；删除文档后的引用处理；导入资料含“忽略此前指令”仍仅按资料保存。

## 10. 后续里程碑

- M2：用户自带模型接入、安全密钥处理、流式或合理加载、错误恢复、结构化输出与设定引用。
- M3：可靠状态校验与事务、NPC 知识边界、事件日志/摘要、正式快照和分支、只影响未来的光环。
- M4：长文本性能、安卓键盘与安全区、网络失败恢复、导入导出、完整端到端验收；再评估 PWA 与 App 封装。

暂不做：多人、共享世界市场、持续后台 NPC 自治、自动地图/立绘、语音、复杂战斗、OCR、云同步冲突、多模型协作引擎。公开代码库不等于承诺这些功能。

## 11. 两个 AI 如何协作

建议第二个 AI 优先承担 M1 接口/数据模型审阅、文档解析样本验证和测试用例设计；当前实现者负责集成、手机界面兼容和发布。先交换方案再改同一文件。

每项任务声明：目标、输入、允许修改的目录、接口约定、验收标准、完成提交。独立分支/工作区，避免两个 AI 同时直接改主分支。项目 owner 决定最终产品范围。

输出必须区分已完成、建议、未验证。改动后提供变更文件、测试命令和实际结果。不能以测试脚本通过推断所有真机都正常，不能把模拟数据描述为真实 AI 功能。

## 12. 可直接交给另一 AI 的开场任务

请先阅读本文件、README.md 和现有源码。墨境已完成 M0，用户认可当前交互方向；不要重新搭建原型或直接接真实模型。请针对 M1-A/M1-B 提交一个最小实现方案：World/Document/Chunk/Entry 数据关系、前后端接口、TXT/MD 导入及原文来源保留、中文检索验证方法、演示与正式数据隔离、迁移和回滚方式、验收样本。先报告与本文冲突或不明确之处，待任务分配后在独立分支实现。不要要求用户提供 API Key。
