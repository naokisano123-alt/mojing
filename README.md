# 墨境 · 手机端文字冒险世界模拟器

React + TypeScript + Vite + Tailwind CSS，配合 FastAPI + SQLite 本地资料库。优先适配安卓手机浏览器，支持浅色和深色主题。

当前包括以下体验：

- **M0 本地试玩**：世界卡片、自由行动输入、小说叙事、角色、图鉴、时间线、存档与分支；剧情由预置数据和关键词规则模拟。
- **M1 世界资料库**：世界持久化，TXT/Markdown/PDF/DOCX 文本导入、分块与原文浏览、中文子串检索、人工设定条目及来源引用。支持草稿恢复、revision冲突处理与来源失效提示。

- **M2-A 叙事实验**：资料库内可选Fake测试或配置OpenAI兼容服务生成Live草案；支持连接测试、停止/重试和引用原文回跳。Key仅放后端内存会话，闲置30分钟后失效。

**冒险记录**支持连续剧情：草案经确认后持久保存，下一步行动参考已确认历史。新旅程可初始化独立角色，并选择采用模型提出且经范围校验的状态变化；M0存档不受影响。仓库支持[私有 HTTPS 部署](deploy/README.md)，现有静态站点仍为早期演示。PDF/DOCX无OCR，检索为字面匹配。

安卓版在世界页点「导出两份文件」，选择文件夹后会保存世界观 JSON 和存档 JSON。两份文件也可分别下载，或打包成 ZIP。回到首页点「导入世界或存档」，可选一份世界观、同一版本的两份 JSON 或墨境 ZIP。单独导入存档时，本机必须有匹配版本的世界观。导入会新建副本，并恢复已确认的回合、角色、物品介绍、世界日志、检查点和分支。迁移文件总大小和 ZIP 解压后的总大小均以 128 MiB 为上限。迁移文件保留文档提取文本，API Key、未确认草案和原始 PDF/DOCX 文件不随迁移。

在世界资料库的「导入新文档」中，可一次选择 20 个资料文件。每份文件独立校验、解析和保存，完成后可查看每份文件的结果。每个世界默认最多保存 100 份资料，部署者可用 `MOJING_MAX_DOCUMENTS_PER_WORLD` 调整总数。

在冒险记录的「当前角色状态 → 背包」点物品名即可查看和编辑介绍。介绍由同一世界的同名物品共享，也会作为携带物品的背景供模型参考。

## 启动

[安卓应用](android/README.md)可打包为 APK，世界资料和存档保存在手机。也可以通过 [Termux 本地试玩](docs/ANDROID_LOCAL.md)。

### 电脑开发环境

从仓库根目录执行，建议Node.js22.18+，Python3.11+。

~~~bash
npm ci
npm run dev
~~~

后端另开终端，先建立并激活Python虚拟环境，再执行：

~~~bash
python -m pip install -r server/requirements.txt -r server/requirements-parsers.txt
python -m uvicorn app.main:app --app-dir server --host 127.0.0.1 --port 8000
~~~

开发时Vite将/api代理到127.0.0.1:8000。手机与电脑在同一局域网时，打开Vite输出的Network地址；电脑需允许对应端口。当前后端按本地单用户设计。

## 使用模型叙事实验

1. 按上方启动前后端，主页进入“世界资料库”，新建世界并导入资料。
2. 进入“叙事实验”。Fake模式免Key，可先检查输入/停止/来源交互。
3. Live模式填写服务商API根地址（通常以/v1结尾，不含/chat/completions）、准确模型名称和Key，建立会话。
4. 主动点击“测试连接”会产生一次极短服务商请求，可能计费。连接成功后输入行动并生成草案。
5. 停止后保留输入，手动重试；关闭连接不能保证服务商未计费。需要移除凭据时点“断开会话”，删除失败会保留重试入口。

真实服务商尚待用户配置验证；标准Chat Completions默认输出额度2048 tokens，服务商需支持相应参数。模型仅能引用本次提供的资料，但程序不能保证叙事完全符合事实。

## 连续冒险

从首页进入资料库世界，即可打开「冒险记录」。点击「连接模型 API」设置服务商和模型，再返回创建真实模型旅程；也可以直接新建免 Key 的模拟旅程。

输入行动→生成草案→核对内容与来源→点击“确认并写入回合”。只有确认后的内容进入历史；刷新后仍可继续。停止/错误保留行动，响应丢失时用“刷新记录 / 恢复草案”核对，避免重复付费调用。可丢弃未确认草案再编辑，已确认回合不可原地改写；可通过检查点恢复为新分支继续。

接口与限制见[M2-B说明](docs/contracts/M2_B_API.md)，验证见[本轮交付](docs/reports/codex-adventure-history.md)。

## 角色与状态

新建旅程可填写角色姓名、起始位置与铜币；体力/精神默认100。生成后的状态提议单独标明“尚未生效”，默认只保存叙事；勾选采用后，确认按钮才同时保存状态变化。每回合留有状态前后快照，重复确认不会重复扣款或加时间。

旧旅程继续原有叙事，新建旅程才能初始化角色。程序可按日志结算押金；其他交易和移动仍需玩家核对模型提议。背包数量账本已实现，装备、技能、战斗和死亡等尚未实现。[接口与边界](docs/contracts/CHARACTER_STATE.md) · [本轮验证](docs/reports/codex-character-state.md)。

## 背包与物品

新建旅程时可添加起始物品及数量；同名输入合并，最多40种、每种9999。草案中的物品增减会单独展示，并与铜币等共用“采用状态提议”确认。余额不足或任意变化非法时整份提议被拒绝，确认重试不会重复获得或消耗物品。

旧角色没有背包字段时显示空背包。Fake可演示固定“测试纪念签+1”，不代表对自由行动的真实判定；装备/耐久/唯一物品实例仍未实现。[规则与限制](docs/contracts/INVENTORY.md) · [本轮验证](docs/reports/codex-inventory.md)。

## 世界日志与更正

冒险记录中的「世界日志与更正」默认收起。日志跟踪押金、约定和秘密知情人；生成新回合时会同时参考当前状态、相关旧日志与摘录，以及最近六个已确认回合。

草案有日志提议时，默认勾选一并采用，可在确认前核对或取消。采用交付、退款或扣留押金的提议时，程序按账本结算一次。手动补记、更正或撤销会保留变更记录，不改写已确认的原文，也不自动改动角色余额。旧回合不会自动补录，可从日志入口手动补记。知情名单给模型提供叙事约束，仍需核对模型实际写出的台词。

## 开局与时间快进

在世界资料页的「开局与日程」可以创建多个开局，填写正文、角色、起始地点、世界时间和初始物品。新旅程可预览并选择开局，也可以自由创建。已开始的旅程保留当时的开局与事件规则，后续改稿适用于新开的旅程。

作者可以设置一次性或循环事件，并指定是否需要玩家停下来决定。玩家界面只展示已经推进到的事件，不提前列出日程。用「指定快进时长」或输入「接下来三天照常做工」可以生成推进草案，单次最多七天。遇到第一个需要决定的事件时，时间停在事件发生的时刻。确认后将时间和事件一并写入回合，回到较早的检查点可以在独立分支重新经历。退出应用期间世界时钟暂停。

可以从「试用细器铺试工」保存示例开局，用模拟旅程试点预设行动。世界包携带开局配置，存档携带旅程快照和已确认的时间结算。

## 检查点与分支

在“冒险记录”的“存档与分支”区域，命名并保存当前已确认检查点；填写分支名称后点击“从此处创建分支”。恢复会保留原路线，复制保存时的剧情、角色、背包和日志，再切换到新路线。第0回合也可保存起点。

未确认草案不包含在检查点中；世界设定资料仍共享，不会随玩家进度回滚。Live分支继续使用当前内存模型连接，Key不会进入存档。此功能不是文件/云备份。[接口与限制](docs/contracts/CHECKPOINTS.md) · [本轮验证](docs/reports/codex-checkpoints.md)。
